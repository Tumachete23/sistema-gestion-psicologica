## Bloqueos reales

- Docker Desktop no expone `dockerDesktopLinuxEngine`. `docker compose up -d --build --wait`
  falla antes de construir imágenes. Pendientes: build Linux, arranque de los cuatro servicios,
  PostgreSQL desde Laravel, Redis desde Laravel y migraciones estándar en PostgreSQL.
  El 28/09 se identificó la causa en el registro de Docker Desktop: `initializing Inference
  manager` falla al acceder al archivo interno `dockerInference` (`The file cannot be
  accessed by the system`). WSL muestra docker-desktop detenido. Iniciar el servicio
  com.docker.service también falla por permisos de Windows. No se restableció Docker,
  no se borraron archivos internos ni se eliminaron distribuciones o volúmenes.
- El puerto 8000 está ocupado por otro servicio PHP. Las pruebas locales se ejecutaron
  temporalmente en 18000 (API) y 15173 (Vite). Para Docker, establecer BACKEND_PORT=18000
  y APP_URL=http://localhost:18000 en el .env raíz antes del arranque.
- El entorno restringido creó Git bajo otra cuenta Windows. Al ejecutar Git con la cuenta
  del usuario se usó una excepción `-c safe.directory` limitada al comando; no se cambió
  la configuración global. No se creó commit ni remoto.

## Retomar validación

1. Iniciar el motor Linux de Docker Desktop y comprobar `docker info`.
2. Ajustar el puerto local según lo indicado arriba.
3. Ejecutar los comandos del README: arranque, migraciones, comprobación PostgreSQL/Redis,
   tests, build y health directo/proxy.
4. Solo si todas las verificaciones pasan, cerrar HU-001. HU-002 permanece sin implementar.
